# CI and Automated Release Management Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add PR-time verification (commit-message linting, tests, build, Prettier) and a merge-time release pipeline (semantic-release: version, changelog, GitHub Release) that deploys both Cloudflare Workers automatically when a release is produced.

**Architecture:** Two new GitHub Actions workflows (`pr.yml`, `release.yml`) plus a new root-level, tooling-only `package.json` (not an npm workspace — `backend/` and `frontend/` keep their own independent installs). semantic-release's `@semantic-release/exec` plugin's `publishCmd` (which only runs when a release was actually determined) drives the Cloudflare deploy, so a `chore`/`docs`-only merge never deploys.

**Tech Stack:** GitHub Actions, semantic-release + plugins (`commit-analyzer`, `release-notes-generator`, `changelog`, `exec`, `git`, `github`), commitlint, husky, Prettier, plain Node (`node:test`) for the one helper script.

**Spec:** `docs/superpowers/specs/2026-09-29-ci-release-automation-design.md`

## Global Constraints

- No npm publish — no `@semantic-release/npm` plugin; nothing in this repo ships to a registry.
- No automated D1 migrations — CI never runs `db:migrate:remote`.
- No branch-protection changes — `main` has none today, so the default `GITHUB_TOKEN` (with `contents: write`) is sufficient; no GitHub App bypass token.
- Prettier only — no ESLint.
- No preview/staging deploy environment for PRs.
- Root `package.json` is tooling-only, **not** an npm workspaces root — `backend/` and `frontend/` are installed and tested independently exactly as today (`cd backend && npm ci && npm test`, `cd frontend && npm ci && npm run build`).
- Single repo-level semantic version and changelog (not independent per-package versions).
- `commit-analyzer` release rules (exact): `feat`→minor, `fix`/`perf`/`revert`/`docs`/`refactor`→patch, `chore`/`test`/`build`/`ci`→no release.
- CI Node version: 24 (matches this repo's `mise use node@lts` convention).
- This repo squash-merges PRs (confirmed empirically) — the PR title becomes the commit on `main`, so it must itself be a valid conventional commit.

- [ ] **Step 1: Write the failing test**

import assert from "node:assert/strict";
import { mkdtempSync, readFileSync, writeFileSync, rmSync } from "node:fs";
import { tmpdir } from "node:os";
import { join } from "node:path";
import { syncPackageVersion } from "./sync-package-versions.mjs";

test("syncPackageVersion updates only the version field", () => {
  const dir = mkdtempSync(join(tmpdir(), "sync-package-versions-"));
  const filePath = join(dir, "package.json");
  writeFileSync(
    filePath,
    `${JSON.stringify({ name: "example", version: "0.0.0", dependencies: { hono: "^4.6.9" } }, null, 2)}\n`,

  assert.equal(updated.version, "1.2.3");
  assert.equal(updated.name, "example");
  assert.deepEqual(updated.dependencies, { hono: "^4.6.9" });

  rmSync(dir, { recursive: true, force: true });
});

test("syncPackageVersion writes a trailing newline", () => {
  const dir = mkdtempSync(join(tmpdir(), "sync-package-versions-"));
  const filePath = join(dir, "package.json");
  writeFileSync(filePath, `${JSON.stringify({ name: "example", version: "0.0.0" }, null, 2)}\n`);

  syncPackageVersion(filePath, "2.0.0");

  const raw = readFileSync(filePath, "utf8");
  assert.ok(raw.endsWith("\n"));

  rmSync(dir, { recursive: true, force: true });
});

- [ ] **Step 2: Run test to verify it fails**

- [ ] **Step 3: Write the implementation**

```js
#!/usr/bin/env node
import { readFileSync, writeFileSync } from "node:fs";

export function syncPackageVersion(filePath, version) {
  const pkg = JSON.parse(readFileSync(filePath, "utf8"));
  pkg.version = version;
  writeFileSync(filePath, `${JSON.stringify(pkg, null, 2)}\n`);
}

const DEFAULT_TARGETS = ["backend/package.json", "frontend/package.json"];

function main() {
  const version = process.argv[2];
  if (!version) {
    console.error("Usage: sync-package-versions.mjs <version>");
    process.exit(1);
  }
  for (const filePath of DEFAULT_TARGETS) {
    syncPackageVersion(filePath, version);
  }
  console.log(`Synced version ${version} to ${DEFAULT_TARGETS.join(", ")}`);
}

if (import.meta.url === `file://${process.argv[1]}`) {
  main();
}
```

Save to `scripts/sync-package-versions.mjs`.

### Task 6: `pr.yml` GitHub Actions workflow

**Files:**
- Create: `.github/workflows/pr.yml`

**Interfaces:**
- Consumes: `commitlint.config.js` (Task 3), `.prettierrc` (Task 2), `backend`'s existing `npm test`, `frontend`'s existing `npm run build`.

- [ ] **Step 1: Create the workflows directory and write the file**

```yaml
name: PR Checks

on:
  pull_request:
    types: [opened, edited, synchronize, reopened]

jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 24
          cache: npm

      - name: Install root dependencies
        run: npm ci

      - name: Validate commit messages
        run: npx commitlint --from ${{ github.event.pull_request.base.sha }} --to ${{ github.sha }} --verbose

      # PRs are squash-merged, so the PR title becomes the commit subject on main
      # that semantic-release reads to decide the version bump. It must be a
      # conventional commit.
      - name: Validate PR title
        env:
          PR_TITLE: ${{ github.event.pull_request.title }}
        run: printf '%s\n' "$PR_TITLE" | npx commitlint --verbose

      - name: Install backend dependencies
        working-directory: backend
        run: npm ci

      - name: Run backend tests
        working-directory: backend
        run: npm test

      - name: Install frontend dependencies
        working-directory: frontend
        run: npm ci

      - name: Build frontend
        working-directory: frontend
        run: npm run build

      - name: Collect changed files for Prettier
        id: prettier_files
        shell: bash
        run: |
          mapfile -t files < <(
            git diff --name-only --diff-filter=ACMRT \
              "${{ github.event.pull_request.base.sha }}...${{ github.sha }}" \
              | grep -E '\.(cjs|js|json|md|mjs|ts|tsx|yaml|yml)$' || true
          )

          if [ ${#files[@]} -eq 0 ]; then
            echo "count=0" >> "$GITHUB_OUTPUT"
            exit 0
          fi

          {
            echo "count=${#files[@]}"
            echo "files<<EOF"
            printf '%s\n' "${files[@]}"
            echo "EOF"
          } >> "$GITHUB_OUTPUT"

      - name: Run Prettier check
        if: steps.prettier_files.outputs.count != '0'
        shell: bash
        run: |
          mapfile -t files <<'EOF'
          ${{ steps.prettier_files.outputs.files }}
          EOF
          npx prettier --check "${files[@]}"
```

Save to `.github/workflows/pr.yml` (create the `.github/workflows/` directory first if needed).

Expected: exits 0, no parse error printed.
